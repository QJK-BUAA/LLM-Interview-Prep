# ML Roadmap 新手友好知识库设计

日期：2026-09-26

## 1. 目标

在 `/Users/bytedance/Desktop/面试/ml-roadmap` 新建一个独立、可离线运行的机器学习知识库。旧项目 `ml-notes` 保持不变，仅作为覆盖范围参考。

目标读者是零基础学习者，最终目标是：

1. 建立从数学、机器学习、神经网络到 Transformer 的连续知识链。
2. 系统掌握 LLM 训练、推理、微调和后训练。
3. 能解释公式、阅读伪代码，并回答算法岗常见面试题。
4. 理解截至 2026 年 9 月的重要后训练方向，包括 OPD 与 OPSD。

## 2. 核心问题

原项目有三个结构性问题：

1. 默认读者已有前置知识，定义后很快进入公式和论文结论。
2. 16 篇内容虽多，但线性代数、微积分、Python/张量、完整策略梯度链等地基不足。
3. 前沿材料与网页正文分离，OPD、OPSD 等新方向没有进入主学习路径。

新项目不做原文润色，而是重写知识组织、章节内容和阅读界面。

## 5. 单章教学契约

每章必须包含以下字段和内容层次：

1. `先修知识`：链接到前置章节，不用未解释概念。
2. `学完能做什么`：3 至 5 个可验证目标。
3. `一句话结论`：先给全局方向。
4. `直觉与类比`：解释概念解决了什么问题。
5. `最小数字例子`：至少一个能手算或跟踪 shape 的例子。
6. `机制图`：使用 HTML/CSS/SVG-free DOM 图示，离线可用。
7. `公式拆解`：先定义符号，再逐步推导，不跳等号。
8. `代码实验`：短小、可独立理解的 Python 或伪代码。
9. `常见误区`：指出相似概念的边界。
10. `方法对比`：说明何时使用、何时不使用。
11. `面试表达`：30 秒回答和追问展开。
12. `自测题`：至少 3 题，答案可折叠查看。

公式不是正文入口。读者即使暂时跳过公式，也应能通过直觉、例子和图示理解主结论。

## 6. OPD 与 OPSD 专章要求

第 19 章必须完整覆盖：

1. 从 SFT 的 exposure bias 和 RLVR 的稀疏标量奖励引出 OPD。
2. OPD 的 student rollout、teacher token distribution、on-policy 数据闭环。
3. forward KL、reverse KL 和常见蒸馏目标的方向差异。
4. OPD 与 SFT、offline KD、PPO/GRPO 的数据来源及监督粒度对比。
5. OPSD 中同一模型的 student context 与 privileged teacher context。
6. 为什么 OPSD 不需要外部大教师，以及 privileged information leakage 风险。
7. 长 CoT 场景中的训练不稳定、机械记忆和可迁移推理信号。
8. Purified OPSD、RLSD、H2SD、Lightning OPD 等方向的定位。
9. 训练伪代码、计算/显存成本、适用前提和失败模式。
10. 面试对比题和方法选择决策树。

涉及 2026 年研究的结论必须引用论文页或作者公开材料，并区分“论文报告”“广泛共识”和“教学解释”。

## 7. 界面与交互

第一屏直接进入学习工作台，不制作营销落地页。

### 桌面端

- 左侧：按 Part 分组的 21 章课程导航、进度状态、搜索。
- 中间：正文阅读区，控制最大行宽。
- 右侧：本章目录、学习目标和章节进度。
- 顶部：品牌名、学习/面试模式切换、主题切换和总体进度。

### 移动端

- 顶部固定工具栏。
- 课程目录和本章目录使用抽屉。
- 正文单列显示，表格和公式允许横向滚动。

### 学习功能

- 学习模式：显示完整教学内容。
- 面试模式：聚焦结论、对比、误区和问答。
- 公式推导可折叠。
- 术语首次出现时可查看简短定义。
- 每节可标记完成，进度写入 `localStorage`。
- 全文搜索标题、标签、摘要与正文。
- 自测题答案默认折叠。
- 代码块提供复制按钮。
- URL hash 保存当前章节和小节，可刷新恢复。

## 8. 视觉系统

风格应像安静、清晰的学习工具，而非营销网站：

- 主色使用蓝色，状态色使用绿色、琥珀色和红色，避免单一色调。
- 卡片圆角不超过 8px，不嵌套卡片。
- 正文 15 至 16px，紧凑标题层级，不使用超大标题。
- 公式、代码、提示、误区使用不同但克制的视觉语义。
- 图示以可读的流程节点、矩阵格和分布条为主，不使用装饰性渐变或光斑。
- 所有固定工具栏、按钮和进度控件使用稳定尺寸，避免内容加载时跳动。

## 9. 技术架构

项目采用无构建步骤的静态应用，确保离线和本地启动简单：

```text
ml-roadmap/
├── index.html
├── README.md
├── app/
│   ├── app.js
│   ├── styles.css
│   ├── renderer.js
│   ├── store.js
│   └── glossary.js
├── content/
│   ├── catalog.js
│   └── chapter-00.js ... chapter-20.js
├── vendor/
│   └── katex/
├── scripts/
│   └── validate-content.mjs
└── docs/
```

章节文件导出结构化对象。渲染器只负责显示，不包含学科内容；状态模块只负责进度和模式；术语表集中维护定义。各模块边界清晰，可独立检查。

数据流：

```text
catalog -> load chapter -> renderer -> DOM
                         -> search index
user action -> store -> localStorage -> progress UI
URL hash <-> router <-> active chapter/section
```

项目复用旧项目本地 KaTeX 字体和运行库，但不复制旧正文。

## 10. 错误处理

- 章节加载失败时显示具体章节名和重试按钮。
- KaTeX 公式渲染失败时保留原始公式文本，不阻断整章。
- `localStorage` 不可用时退化为会话内状态。
- 复制 API 不可用时选中代码并提示手动复制。
- 无搜索结果时保留搜索词并提供清除动作。
- 非法 URL hash 回退到第 00 章。

## 11. 内容质量与引用

- 不把未经核验的博客判断写成事实。
- 经典概念优先引用原论文、教材或官方文档。
- 2025 至 2026 的前沿方法优先引用 arXiv 原文和作者材料。
- 每个缩写首次出现时给出英文全称和中文解释。
- 每个公式中的符号必须在公式前或公式后紧邻定义。
- 不使用“显然”“容易得到”等跳步措辞。
- 不宣称某方法是 SOTA，除非说明数据集、模型规模、评估设置和来源。

## 12. 验收标准

### 内容

- 21 章全部存在，无占位章节。
- 原项目 16 篇主题全部映射到新章节并被重新表述。
- 每章满足第 5 节的教学契约。

- 所有章节至少包含一个例子、一个图示、一个代码/伪代码块和三道自测题。
- 前沿章节提供来源并明确证据等级。

### 功能

- 首页直接展示第 00 章。
- 章节切换、搜索、模式切换、目录跳转、进度保存、答案折叠和代码复制可用。
- 刷新后恢复当前章节和完成状态。
- 桌面、平板和手机尺寸无文字遮挡或不可达控件。

### 工程

- `python3 -m http.server` 可启动。

- 浏览器控制台无 JavaScript 错误。
- KaTeX、正文和章节资源均返回成功状态。
- 使用桌面与移动视口截图进行最终视觉检查。
