## 确认修订

### F20-1（归一化清晰度）：VAPO 正例项首式应与论文及代码同口径

- 位置：20 `derivation` 的 `L_NLL=-E_(x,y)~D+ [sum_t log pi]`。这是每正例的序列 NLL 和取均值；原论文 v1 §4.3 式 (9) 是所有正例的有效 token 总均值，当前章后续专题和代码也用后者。
- 原文已提醒归一化会改变 mu 尺度，因此不判为代码数学错误；但章节标题为完整推导且公式直接标 VAPO，读者仍可能把这个尺度当论文目标。
- 独立例：两条正例长度 2、8，每 token NLL 为 1、3。首式得到 13，论文/代码得到 2.6；两者在固定 batch 中方向相同但尺度差五倍，与 PPO 主项混合后相对强度不同。不能将其混同 F19-1 的“逐句均值 vs 全 token 均值”。
- 修法：首式直接用正例 token 总和/总有效长度，并定义 `N_+`；若介绍序列和或逐句均值，明确为另一个可选目标。保留空正例为零和 mu 尺度说明。

### F23-1（奖励边界）：乘法门控只在安全分为零时完全抹去帮助性

- 位置：23 `derivation` 的“不能靠高帮助性抵消被识别的不安全输出”。
- Safe-Completions v1 §2.2 明确 `h,s∈[0,1]`，严重/确定违规为零，边缘低严重度违规允许中间值。
- 独立反例：`h=.9,s=.5` 得 .45，高于 `h=.3,s=1` 的 .3。因此乘积并不对所有非满分安全样本实施零容忍硬约束。
- 修法：明确范围和中间分含义，将该结论限定为 `s=0`；加一句非零安全分仍存在分数取舍。已有“评分器不是真实安全证明”的说明保留。

### F24-1（信息条件）：特权输入不可用于测试，不等于知识无法迁移

- 位置：24 `comparison` 的 OPD/OPSD 风险列：“OPSD 额外信息不可迁移”。
- 第 19 章的信息条件分析给出了可迁移部分与不可消去下界，训练中的额外上下文可以帮助学知识或解题过程；并非所有额外信息都无法通过参数转移。
- 修法：“教师成本；OPSD 测试须移除特权输入，并检验信息依赖与泛化”。与 19 的正文和本章其他解释统一。
